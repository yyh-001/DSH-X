`0.1.27-rc.3` 是 `0.1.27` 的第三版预发布：修复「核心更新了、外壳还是旧版」时管理页打不开（401）的问题。外壳代码没变，但重新出了安装包；已经卡在 401 的用户直接装这一版即可恢复。

### 问题修复

- 修复旧外壳打开管理页被 401 挡住：新核心要求管理页带 launch token，而旧外壳只会打开不带 token 的根地址。现在本机顶层页面导航会自动 303 到带 token 的同一地址，换好 cookie 后再跳回干净地址。
- 兼容跳转只对本机回环的顶层导航生效：局域网访客和页面里的脚本 / API 请求仍然必须带 token。

### 其他变更

- 外壳与核心版本都升到 `0.1.27-rc.3`。外壳逻辑没有改动，安装包重新构建，方便已经卡住的用户覆盖安装恢复。
- 如果你现在停在 401：安装本版安装包；应急也可以打开 `manager-token.json` 里的 `url`（带 `?token=`）进入管理页。

## English

`0.1.27-rc.3` is the third preview of `0.1.27`: it fixes the manager page returning 401 when the core was updated but the shell was still old. The shell code is unchanged, but the installers were rebuilt; anyone currently stuck at 401 can install this build to recover.

### Bug Fixes

- Fix the old shell being blocked by the manager page's 401: the new core requires a launch token, while the old shell only opens the root URL without one. A local top-level navigation is now redirected with 303 to the same URL carrying the token, the cookie is set, and the page returns to the clean URL.
- The compatibility redirect only applies to loopback top-level navigations: LAN visitors and in-page script/API requests still require the token.

### Chores

- Shell and core versions are now `0.1.27-rc.3`. The shell logic did not change; installers are rebuilt so users who are already stuck can reinstall and recover.
- If you are stuck at 401: install this build, or open the `url` (with `?token=`) from `manager-token.json` as an emergency workaround.
