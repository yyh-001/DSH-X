`0.1.26` 汇总了 `0.1.25` 之后的改动：新增 WSL 支持、安装包改为从 npm 取核心、插件页可直接添加和卸载插件，并重做了启动项日志。rc 通道用户会自动转回稳定通道。

### 新增功能

- 支持 WSL：可在 WSL 发行版里新建、编辑和启动 dsh 启动项，并直接打开它的网页；「启动环境」选择窗左栏同时列出本机目录和 WSL 发行版，可查看发行版里的 Profile 与插件、添加 WSL 目录、在资源管理器打开目录、删除 WSL Profile。
- WSL 启动项支持设置项目目录，可用原生对话框选择，回填 Linux 路径。
- 安装包不再内置核心：首次启动从 npm 取与外壳兼容的最新核心，之后跟随通道更新；核心下载窗口显示实时进度和实际下载源。
- 插件页支持添加和卸载插件：npm 包名、本地绝对路径、Git 地址都可以；装完自动把 bundle 挂进层栈，卸载时一并清掉依赖、层栈条目和补丁层里的开关残留。
- 首页插件弹窗的「更多操作」新增 Profile 备份与回退入口。
- 启动项日志改成页签：原始日志 / 耗时构成 / 空间构成 / 插件诊断，只有采到数据的页签才出现。
- 每个已安装版本显示磁盘占用，版本弹窗顶部显示总占用。
- 输入框拖拽文件 / 文件夹变成路径引用：工作区内文件为 `@相对路径`，工作区外为 `@绝对路径`，文件夹为目录引用；图片仍按上传处理。
- 界面语言新增「系统默认」并设为默认，首次启动跟随系统语言。
- 发布同时提供 Linux arm64 的 AppImage / deb 与 `latest-linux-arm64.yml`。

### 体验优化

- 首启下载窗口显示已下载 / 总大小 / 百分比和实际下载源；镜像 6 秒超时就切官方源，tarball 从镜像拉不动时也会换另一个源的同版本重试。
- 配置回退后自动按还原的清单重装依赖；「修复环境」（安全启动）后插件列表如实显示为关闭。
- 插件弹窗固定高度，「更多操作」菜单不再被卡片底边裁掉；配置回退与「立即备份」有进度条和加载动画。
- 启动项日志的耗时构成把原生/GC 按调用方归到包，插件耗时按 import 依赖图归因；空间构成拆成插件本体 / 插件依赖 / 运行时 / 配置与数据。
- 界面图标统一到 Lucide（ISC，描边 1.8）；托盘与应用图标按新设计重出，Windows 托盘按 DPI 取 16 / 24px 原生帧，缩放后不再发虚。
- 启动页日志弹窗重做，加入空间占用页签；首页左上角更新提示改成图标 + 状态点。
- 默认关闭水面背景（整页 WebGL 动画），降低 GPU 占用；多实例的界面语言统一跟随 `settings.json`。
- 首启挑选核心时遵守 npm dist-tag 与 `deprecated`，把 `latest` / `rc` 指回旧版即可撤回坏核心。
- 磁盘占用统计每棵树只走一遍并按安装指纹缓存；插件耗时构成不再把 dsh 自身与官方框架开销摊给插件。
- 管理页：跨目录复制的建议名避开目标目录里已有的 Profile；添加插件失败在弹窗关掉后也会提示。

### 问题修复

- 修复安装盘不是 `%APPDATA%\DSH`、系统又没有 pnpm 时，DSH 页面和 agent 工具的插件安装 / 更新 / 卸载在 pnpm 启动前就失败（#102）。
- 修复「添加启动项」会话隔离档里，目录下拉中的长路径把整行撑出弹窗、省略号和右侧下拉箭头看不见的问题。
- 修复慢机器上 dsh 启动被 instance-link 的 5 秒握手超时自杀；安全启动的补丁层备份在管理器重启后能识别并恢复入口。
- 首启下载的核心起不来时记入坏版本列表，不再「下载 → 回退 → 再下载」死循环；目录不可写、磁盘满等环境问题不再被当成坏核心删掉并永久拉黑，核心自身代码错误仍按原逻辑回退（#96，感谢 @Arrosam）。
- 旧 DSH_HOME 删除或换盘后清理 `environmentPorts` 里遗留的端口钉子；外接盘没挂上时不再清掉它的固定端口（#90）。
- `git@host:user/repo` 形式的插件装完能挂载；没有 `bundles` 字段的清单插件不再全部显示关闭；同一插件有两块补丁时启用不生效（#94）。
- 首启下载窗口的注入脚本语法错误导致进度、下载源和文案不更新；`runtimeNode()` 不再优先使用旧安装残留的 `node.exe`。
- WSL：修正 `wsl.exe` 输出解码与等待、端口复用、脚本安装和跨发行版探测；切换界面语言后所有已打开的实例立即同步。

### 其他变更

- 外壳与核心版本都升到 `0.1.26`；rc 通道用户会转回稳定通道。
- 核心 npm 包与 CLI 包随本 tag 一起发布。
- macOS 最低版本仍是 13（Electron 44 / Chromium 152 的要求）。

## English

`0.1.26` collects the changes since `0.1.25`: WSL support, installers that fetch the core from npm, adding and removing plugins from the plugins page, and a rebuilt launch log. Users on the rc channel return to the stable channel automatically.

### New Features

- WSL support: create, edit and start dsh launch entries inside a WSL distro and open its web UI directly. The launch-environment picker lists local directories and WSL distros together, shows the profiles and plugins inside a distro, and can add WSL directories, open them in the file manager, or delete a WSL profile.
- WSL launch entries support a project directory picked with the native dialog, filled back as a Linux path.
- Installers no longer bundle the core: the first launch fetches the newest core compatible with the shell from npm and follows the channel afterwards; the download window shows live progress and the actual source.
- Add and remove plugins from the plugins page: npm names, local absolute paths and Git URLs. Installed bundles are mounted automatically; removal also cleans dependencies, the bundle entry and leftover patch-layer switches.
- The home plugin dialog's "More actions" menu now has profile backups & rollback.
- The launch log is now tabbed: raw log / time breakdown / storage breakdown / plugin diagnosis, with only tabs that have data shown.
- Each installed version shows its disk usage, with the total at the top of the dialog.
- Dragging files or folders onto the composer creates path references: workspace files become `@relative-path`, files outside become `@absolute-path`, folders become directory references; images are still uploaded.
- The interface language gains "System default", now the default for first launch.
- Linux arm64 AppImage / deb and `latest-linux-arm64.yml` are published alongside the x64 artifacts.

### Improvements

- The first-launch download window shows downloaded / total / percent and the actual source; mirror metadata times out after 6 seconds and falls back to the official registry, and a tarball that fails from one source is retried from the other.
- Rolling back a profile reinstalls dependencies from the restored manifest; after "Repair environment" (safe start) the plugin list shows removed bundles as off.
- The plugin dialog has a fixed height so the "More actions" menu is no longer clipped; rollback and "Back up now" have progress bars and loading states.
- The time breakdown attributes native/GC samples to the calling package and plugin time along the import graph; the storage breakdown splits plugin code / plugin dependencies / runtime / config & data.
- Icons are unified on Lucide (ISC, 1.8 stroke); tray and app icons are redrawn, with Windows taking native 16 / 24px frames per DPI so scaling no longer blurs them.
- The launch log dialog is rebuilt with a storage tab; the home update hint becomes an icon with a status dot.
- The water background (full-page WebGL animation) is off by default, reducing GPU usage; all instances follow the interface language in `settings.json`.
- First-launch core selection respects npm dist-tags and `deprecated`, so pointing `latest` / `rc` back to an older version withdraws a bad core.
- Disk usage is walked once per tree and cached by install fingerprint; plugin time no longer carries dsh and framework overhead.
- Manager UI: cross-directory copy suggestion names avoid profiles already in the target; plugin install failures are reported even after the dialog closes.

### Bug Fixes

- Fix plugin install / update / uninstall from the DSH page and agent tools failing before pnpm starts when the install drive is not `%APPDATA%\DSH` and no system pnpm is available (#102).
- Fix the target-directory dropdown in "Add launch" (Session isolation) letting a long path push the row past the dialog and hiding both the ellipsis and the caret.
- Fix dsh killing itself on the 5-second instance-link handshake timeout on slow machines; safe-start patch-layer backups are recognized and restorable after a manager restart.
- A core that fails to start on first launch is recorded as bad, ending the "download → roll back → download again" loop; environment failures such as unwritable directories or a full disk no longer delete the core or blacklist it permanently, while core code errors still roll back as before (#96, thanks @Arrosam).
- Port pins left in `environmentPorts` are cleaned up after an old DSH_HOME is deleted or moves to another drive; an external drive that is not mounted no longer loses its pinned ports (#90).
- Plugins installed from `git@host:user/repo` mount correctly; manifests without a `bundles` field no longer show every plugin as off; enabling a plugin with two patches now works (#94).
- A syntax error in the first-launch download window's injected script left progress, source and status text frozen; `runtimeNode()` no longer prefers a stale bundled `node.exe`.
- WSL: fix `wsl.exe` output decoding and waiting, port reuse, script installation and cross-distro probing; all open instances pick up an interface-language change immediately.

### Chores

- Shell and core versions are both `0.1.26`; rc users return to the stable channel.
- The core npm package and the CLI package are published with this tag.
- macOS minimum remains 13 (required by Electron 44 / Chromium 152).
