`0.1.26-rc.6` 汇总了 rc.5 之后的改动：WSL 并进启动环境选择、输入框拖拽路径引用、界面图标统一到 Lucide，并修掉插件安装在特定环境下失败等问题。外壳和核心都有改动，rc 通道会收到新安装包。

### 新增功能

- WSL 并进「启动环境」选择窗：左栏同时列出本机目录和 WSL 发行版，可直接查看发行版里的 Profile 与插件、添加 WSL 目录、在资源管理器打开目录、删除 WSL Profile。
- WSL 启动项支持设置项目目录，可用原生对话框选择，回填 Linux 路径。
- 输入框拖拽文件 / 文件夹变成路径引用（#91）：工作区内文件为 `@相对路径`，工作区外为 `@绝对路径`，文件夹为目录引用；图片仍按上传处理。
- 界面语言新增「系统默认」并设为默认，首次启动跟随系统语言。
- 发布同时提供 Linux arm64 的 AppImage / deb 与 `latest-linux-arm64.yml`，x64 产物名和清单保持不变。

### 体验优化

- 界面图标统一到 Lucide（ISC，描边 1.8）；托盘与应用图标按新设计重出，Windows 托盘按 DPI 取 16 / 24px 原生帧，缩放后不再发虚。
- 启动页日志弹窗重做，加入空间占用页签；隔离页与插件行操作按钮位置调整。
- 首页左上角更新提示改成图标 + 状态点。
- 默认关闭水面背景（整页 WebGL 动画），降低 GPU 占用。
- 多实例的界面语言统一跟随 `settings.json`，不再各读各的。

### 问题修复

- 修复安装盘不是 `%APPDATA%\DSH`、系统又没有 pnpm 时，DSH 页面和 agent 工具的插件安装 / 更新 / 卸载在 pnpm 启动前就失败（#102）。
- 目录、权限、磁盘等环境类启动失败只报错，不再删除 `core/current`、写入坏版本黑名单或自动重启；核心自身代码错误仍按原逻辑回退（#96，感谢 @Arrosam）。
- 设置里切换界面语言后，所有已打开的实例立即同步。

### 其他变更

- 外壳与核心版本都升到 `0.1.26-rc.6`；外壳层有改动（拖拽桥、WSL、托盘图标、图标资源），rc 通道会收到新安装包。
- 核心 npm 包与 CLI 包随本 tag 一起发布。
- 新增 `dev:core` / `dev:shell` / `dev:app` 本地验收脚本，日常测试不再需要每次打包（开发者向）。
- macOS 最低版本仍是 13（Electron 44 / Chromium 152 的要求）。

## English

`0.1.26-rc.6` collects the changes since rc.5: WSL merged into the launch-environment picker, drag-to-path references in the composer, Lucide icons across the UI, and a fix for plugin installs failing in certain environments. Both the shell and the core changed, so rc users will receive a new installer.

### New Features

- WSL is now part of the launch-environment picker: the left column lists local directories and WSL distributions together, with their profiles and plugins, plus adding WSL directories, opening them in Explorer, and deleting WSL profiles.
- WSL entries can set a project directory picked through the native dialog and stored as a Linux path.
- Dragging files or folders onto the composer creates path references (#91): workspace files become `@relative-path`, files outside become `@absolute-path`, folders become directory references; images are still uploaded.
- The UI language adds a "System default" option and uses it by default, following the system language on first launch.
- Releases now also ship Linux arm64 AppImage / deb and `latest-linux-arm64.yml`; x64 artifact names and manifests are unchanged.

### Improvements

- UI icons are now Lucide (ISC, 1.8 stroke); the tray and app icons were redrawn, and the Windows tray picks native 16 / 24px frames per DPI so it stays sharp when scaled.
- The launch log dialog was reworked with a storage-usage tab; the isolation page and plugin-row buttons were rearranged.
- The update hint in the top-left corner is now an icon plus a status dot.
- The water background (a full-page WebGL animation) is now off by default, reducing GPU usage.
- Multiple instances now share the UI language from `settings.json` instead of reading their own copy.

### Bug Fixes

- Fix plugin install / update / uninstall from the DSH page and agent tools failing before pnpm starts when the install drive is not `%APPDATA%\DSH` and no system pnpm is available (#102).
- Environment startup failures such as directory, permission or disk errors now only report the error: they no longer delete `core/current`, blacklist the version or restart automatically; core code errors still roll back as before (#96, thanks @Arrosam).
- Changing the UI language in settings now updates every open instance immediately.

### Chores

- Shell and core versions are both `0.1.26-rc.6`; the shell layer changed (drag bridge, WSL, tray icon, icon assets), so the rc channel receives a new installer.
- The core npm package and the CLI package are published with this tag.
- New `dev:core` / `dev:shell` / `dev:app` local acceptance scripts, so routine testing no longer needs a full package build (for developers).
- macOS minimum remains 13 (required by Electron 44 / Chromium 152).
