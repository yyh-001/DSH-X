`0.1.26-rc.5` 汇总了 rc.4 之后的一批功能与修复：新增 WSL 启动项支持，插件诊断并入日志弹窗，并修掉首启核心、安全启动还原、跨目录复制等问题。这次外壳和核心都有改动，rc 用户会收到新的安装包。

### 新增功能

- 支持 WSL：可以在 WSL 发行版里新建、编辑和启动 dsh 启动项，并直接打开它的网页；探测、安装、重启和端口复用都按发行版处理。
- 插件诊断并入原始日志弹窗，作为其中一个页签出现，不再单独开窗。

### 体验优化

- 首次启动按系统语言选择界面语言，不再固定中文。
- 核心更新通道自动跟随外壳通道，rc 外壳不会再去拿正式版核心。
- 首启挑核心遵守 npm dist-tag 与 `deprecated`：把 `latest` / `rc` 指回旧版即可撤回坏核心。
- 磁盘占用统计每棵树只走一遍，并按安装指纹缓存（落盘 `size-cache.json`），管理器重启后仍命中，大环境明显更快。
- 插件耗时构成不再把 dsh 自身与官方框架开销摊给插件；pnpm 隔离布局按真实包归属，中文 profile 名也能找到自己的报告。
- 管理页：跨目录复制建议名避开目标目录已有的 Profile；添加插件失败在弹窗关掉后也会提示；空间构成加载中不再叠在原始日志页签下。

### 问题修复

- 首启下载的核心起不来时记入坏版本列表，不再「下载 → 回退 → 再下载」死循环；目录不可写、磁盘满等环境问题不再被当成坏核心删掉并永久拉黑。
- 外接盘没挂上时不再清掉它的固定端口；移除用户目录或删除启动项时仍会释放对应端口。
- `git@host:user/repo` 形式的插件装完能挂载；没有 `bundles` 字段的清单插件不再全部显示关闭；同一插件有两块补丁时启用不生效（#94）。
- 连续安全启动时还原入口指向最早那份备份，还原后不再冒出旧备份；建目录失败回滚不再删掉用户的悬空符号链接。
- 配置回退后只在真的重装过依赖时才提示「已重装依赖」；Profile 重装依赖不再抢整合包安装的进度条。
- WSL：修正 `wsl.exe` 输出解码与等待、端口复用、脚本安装和跨发行版探测。
- 保留名只在新建 Profile 时拦截，已有 `desktop` 可以复用；目标已存在时的复制提示与回退文案一并修正。

### 其他变更

- 外壳与核心版本都升到 `0.1.26-rc.5`；外壳层有改动，rc 通道会收到新安装包。
- 核心 npm 包等 Windows / Linux 测试通过后再发布；纯核心预发布补 `latest-linux.yml`，Linux AppImage 检查更新不再 404。
- macOS 最低版本仍是 13（Electron 44 / Chromium 152 的要求）。

## English

`0.1.26-rc.5` collects the features and fixes since rc.4: WSL launch entries, plugin diagnostics folded into the log dialog, and fixes for first-launch core selection, safe-start restore and cross-directory profile copies. Both the shell and the core changed, so rc users will receive a new installer.

### New Features

- WSL support: create, edit and launch dsh entries inside a WSL distribution and open its web UI directly; probing, installation, restart and port reuse are handled per distribution.
- Plugin diagnostics are now a tab inside the raw log dialog instead of a separate window.

### Improvements

- The first launch picks the UI language from the system instead of always using Chinese.
- Core updates now follow the shell channel automatically, so an rc shell no longer pulls a stable core.
- First-launch core selection honors npm dist-tags and `deprecated`: pointing `latest` / `rc` back to an older version retracts a bad core.
- Disk usage scans each tree once and caches by install fingerprint (`size-cache.json`), so the cache survives manager restarts and large environments are much faster.
- Plugin time breakdown no longer charges dsh/framework overhead to plugins; pnpm's isolated layout is attributed to the real package, and reports for non-ASCII profile names are found again.
- Manager page: cross-directory copy names avoid profiles already in the target directory; add-plugin failures still notify after the dialog is closed; the storage breakdown no longer stacks under the raw log tab while loading.

### Bug Fixes

- A first-launch core that fails to start is recorded in a failed-version list instead of looping download → rollback → download; environment failures such as unwritable directories or a full disk no longer delete and permanently blacklist a valid core.
- Port pins for an unmounted external drive are no longer cleared; removing a user directory or a launch entry still releases its port.
- Plugins installed as `git@host:user/repo` are mounted after installation; manifests without a `bundles` array no longer show every plugin as disabled; enabling a plugin with two patch blocks works (#94).
- Consecutive safe starts point the restore entry at the oldest backup, and old backups no longer reappear after restoring; rolling back a failed directory creation no longer deletes the user's dangling symlink.
- After a config rollback, "dependencies reinstalled" is only reported when they really were; profile reinstalls no longer steal the integrator's progress bar.
- WSL: fixed `wsl.exe` output decoding and waiting, port reuse, script installation and cross-distribution probing.
- Reserved profile names are only blocked when creating a profile, so an existing `desktop` can be reused; copy hints and rollback wording were corrected as well.

### Chores

- Shell and core versions are both `0.1.26-rc.5`; the shell layer changed, so the rc channel receives a new installer.
- The core npm package is published only after Windows / Linux tests pass; pure-core prereleases now also copy `latest-linux.yml`, so Linux AppImage update checks no longer 404.
- macOS minimum remains 13 (required by Electron 44 / Chromium 152).
